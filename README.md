# BookMatch — що почитати далі

Вебзастосунок, який радить книги на основі вже прочитаних. Оберіть одну або кілька книг, що вам сподобались, і BookMatch покаже схожі книги та пояснить, чому вони рекомендовані.

## Можливості

- **Пошук книги** за назвою або автором серед тисяч книг
- **Рекомендації за однією або кількома прочитаними книгами** (до 5)
- **Пояснення кожної рекомендації**: «Схожа на книгу X: N спільних читачів»
- **Фільтри**: мінімальна оцінка, роки видання, «без книг тих самих авторів»
- **Популярне**: топ книг за зваженим рейтингом для тих, хто не знає, з чого почати

## Як це працює

Застосунок використовує **колаборативну фільтрацію: item-based kNN**. Дві книги вважаються схожими, якщо їх однаково оцінюють одні й ті самі читачі.

1. Побудовано матрицю «читач × книга» з явних оцінок 1–10. Різні видання однієї книги (різні ISBN) об'єднуються.
2. Від оцінок віднімаємо середню оцінку кожного читача, щоб врахувати, що хтось оцінює суворіше, а хтось м'якше.
3. Пораховано **косинусну подібність** між книгами. Якщо спільних читачів мало, подібність зменшується (shrinkage), щоб випадкові збіги не потрапляли в рекомендації.
4. Для обраних книг підсумовано подібність і показуємо топ-N.

## Дані

[Book Recommendation Dataset (Book-Crossing)](https://www.kaggle.com/datasets/arashnic/book-recommendation-dataset): ≈271 тис. книг, ≈279 тис. користувачів, ≈1,15 млн оцінок.

Під час підготовки:
- залишено лише явні оцінки (1–10); оцінка 0 у цьому датасеті означає неявну взаємодію;
- відкинуто книги з менш ніж 10 оцінками і читачі з менш ніж 5 оцінками;
- виправлено некоректні роки видання.

## Структура проєкту

```
bookmatch/
├── app.py                 # вебінтерфейс (Streamlit)
├── recommender.py         # модель рекомендацій (item-based kNN)
├── prepare_data.py        # підготовка даних: CSV → компактна модель
├── model/                 # готова модель (створює prepare_data.py)
├── data/                  # сюди кладуться CSV з Kaggle (не потрапляють у git)
├── notebooks/
│   └── BookMatch_prototype.ipynb   # етап 2: аналіз даних і порівняння моделей
├── requirements.txt
└── .streamlit/config.toml # тема оформлення
```

## Обмеження та плани

- Дані зібрано у 2004 році, тому новинок немає.
- Нові книги без оцінок не можна порекомендувати (проблема «холодного старту»). Рішення: додати контентні ознаки, як-от автор, видавництво, жанр через Google Books API.
- Плани: персональні рекомендації за профілем читача (SVD), врахування неявних оцінок.
